## Current Status

M1 to M6 are done: the unified schema, the adapter interface and error taxonomy, the mock provider, the `POST /v1/chat` endpoint with its error mapping, and the non-streaming Claude adapter, chosen with `LLMGATEWAY_PROVIDER`. On 2026-11-03 the repo moved to the autonomous workflow in CLAUDE.md: work happens on `main`, with tester and reviewer subagents, `scripts/check.ps1`, and a `live` test marker. M7 is done: the non-streaming Gemini adapter. M8 is done:
- Clients send a model alias.
- A TOML config named by `LLMGATEWAY_CONFIG` maps each alias to (provider instance, provider model) pairs and is validated at startup. Without it, a built-in mock-only default is used.
- The router goes down each alias's entries in order (M11).
- `LLMGATEWAY_PROVIDER` is no longer read; if it is set, startup stops.

M9 is done: the router retries retryable failures with full-jitter backoff, honors `retry-after` up to 5 s, applies a per-attempt timeout and a total deadline, does not retry a 2xx whose status it sees (D-052), and logs every failed attempt with the provider status and a fixed reason.

M10 is done: each provider instance has an in-process circuit breaker. 15 failures in the last 20 outcomes open it, the router checks it before every attempt, a refused request gets 503 `provider_circuit_open`, and every state change writes one `breaker_state_change` line.

M11 is done: a non-streaming request goes down its alias's list when an entry fails for anything but a bad request, under one 90 s deadline with 30 s kept for the next entry. The router checks the client before each retry and each move, and a client that has gone gets no further call (`status=499`). The response names the instance that served in `provider_instance`, and `LLMGATEWAY_FAULTS` fails mock instances on demand.

M12 is done: `stream=true` streams through one event shape for Claude, Gemini and the mock, `delta` events then one `end` that carries what `ChatResponse` carries. Retries, the breaker and fallback apply up to the first event. After it, a failure ends the stream with an `error` event, and a client that leaves or stalls closes the upstream at once. Gemini keeps `MINIMAL` thinking and reports usage as the non-streaming path does. The owner's live run on 2026-11-11 passed both live streaming tests (7 passed in all).

M13 is done: `docker compose up --build --wait` starts the api, Postgres and Redis from a clean clone, with every image pinned by digest. GitHub Actions runs `check.ps1` on Linux and the integration tests against the Compose stack on every push, with no secrets. Every log time is UTC with `+00:00`.

M14 is done: every request but `/healthz` needs `Authorization: Bearer lgw_<id>_<secret>`, checked before the body is read. Postgres keeps only the key's SHA-256; it is found by id and compared in constant time. Every bad key gets the same 401 `invalid_api_key`, and a key that cannot be checked gets 503 `auth_unavailable`. Found rows are cached for 10 s, so revocation takes effect within that. Keys are made with `python -m llmgateway.keys`, and Compose runs the migrations before the api starts. Each request carries its key id and tenant forward as `request.state.principal`.

M15 is done: every adapter attempt, retries, fallback attempts, failures and streams cut short included, becomes one row in `usage_records` with the key's tenant, the alias, instance, model, attempt, outcome, the provider's own token counts (last value, never summed or capped) and the cost in integer nano-dollars from a dated, sourced price table that is checked at startup. Records are queued and written in batches off the response path; a failed write is logged and lost (D-095 to D-100).

D-101 is done (2026-11-12, before M16): every stream attempt that stops early also records the characters it delivered to the client and an estimated output token count, in their own columns from migration 0003, never in the reported counts or the cost.

M16 is done: after auth and before the body is parsed, a body over 1 MiB gets 413 `request_too_large` (`Content-Length` refused unread, chunked bodies counted), then each request takes one token from its API key's bucket in Redis through one Lua script that reads Redis's clock, so the limit is atomic and shared by every worker and instance. A key with no token gets 429 `rate_limited` with `Retry-After`, reaches no provider and is not billed. Since D-106's amendments, a Redis that fails at once, or a limiter breaker that is open, lets the request through with a `ratelimit_unavailable` line (the limiter fails open, unlike auth), while a take that gets no answer within 1 s is shed with 503 `rate_limit_timeout`; a connection Redis closed is retried once (D-102 to D-109).

M17 is done: a client opts in with `x-gateway-cache: use` on a non-streaming request with no temperature above 0, and an identical request from the same tenant is answered from Redis for 300 s: no provider call, cost 0, one usage row with `cache_hit` (migration 0004). The key is a SHA-256 over the tenant, alias, its entries and every answer-changing field, so tenants never share an entry. Only complete first-entry answers up to 256 KiB are stored. Redis down or slow bypasses the cache through its own pool and breaker, never failing a request; every 200 says `hit`, `miss` or `bypass` (D-110 to D-117). A Redis restart no longer costs one failure per pooled connection: a closed connection is retried once (D-106).

M18 is done: the measurements from PLAN.md were pre-registered and run with k6 against the mocks, three times each. The results are in [docs/RESULTS.md](docs/RESULTS.md):

- the accounting cross-check: every run matched.

## Lessons

Distilled from the mistakes logs. The full history is in [docs/archive/2026-11-sessions.md](docs/archive/2026-11-sessions.md) (to the end of M11), [docs/archive/2026-11-m12-sessions.md](docs/archive/2026-11-m12-sessions.md) (M12), [docs/archive/2026-11-m13-m14-sessions.md](docs/archive/2026-11-m13-m14-sessions.md) (M13, M14) and [docs/archive/2026-11-m15-sessions.md](docs/archive/2026-11-m15-sessions.md) (M15).

1. Add up every count before recording it, never copy a subagent's totals unchecked, and keep the script behind any figure in a D-entry.
2. Read the installed source for library behavior: redirects, `DecodingError`, read order, disconnects, line splitting. A default is not a guarantee, so pin it with a test.
3. A claim needs its evidence first: a mitigation in a D-entry must be true in the code, and "host time" needs a measurement, not a guess.
4. Spec first, and spec everything a test will pin. A behavior with no sentence behind it leaves mutants nothing to be judged against.
5. When a behavior changes, search README.md, FLOW.md, comments and `.env.example` for the old wording. The D-entry and FLOW.md change together.
6. Do not write `src/` while the tester is in Mode 1. Say exactly what a red run ran against, and group it from `--junitxml`, because terminal lines are cut off.
7. A failure test asserts the exact outcome. "200 or 502" proves nothing.
8. Spec cancellation and disconnects as their own paths. A cancel can land in the turn a task finishes, so close what that task produced.
9. Leak tests cover every path, position and log level, with planted values, and a leak mutant belongs in every catalog. Check what a capture can see: `caplog` was blind to DEBUG lines (D-065).
10. A mutant stopped only by a harness limit is hung, not caught. Test a close with an upstream that is not a generator, because a generator closes itself when it raises or runs out.
11. Mutation harnesses write durable results, match each file's line endings, and finish with `git diff -- src/` empty. Edit scripts run all or nothing, and `git diff` is read before every commit.
12. In this shell, write long text and edits with the Write or Edit tool and commit with `git commit -F <file>`. Bash heredocs have broken in four milestones, and an empty confirming `grep` means the edit did not run.
13. Prove serving behavior on a real server and a real socket, not only in-process.
14. The reviewer's brief states its Bash limit, each slip by name, and no background runs.
15. On Windows each asyncio loop opens a loopback socketpair, so parallel test runs exhaust the ephemeral ports. Keep mutation workers to 6 or fewer, or avoid TIME_WAIT. The loops are one per async test, not real servers (D-083).
16. A guard's spec names every part of the input it checks: for a URL, the scheme and the parsed host, not "the host". A local-time bug needs a test under a non-UTC `TZ`, because CI is UTC (D-082).
17. Code that only a real database can exercise still needs default-run tests: put a fake driver or pool behind the store and test the error mapping, SQL shape and results there, and keep the real database for the integration proof (M14: 16 `keystore.py` mutants).
18. A leak check scans only what the gateway wrote. A probe that prints the planted value it later searches for fails for the wrong reason, and so does a signature pin nobody moved when the spec added a parameter (M15).
19. A timeout that decides between failing open and failing closed is measured under a burst on a cold instance, not reasoned from a healthy round trip: on one event loop it times the whole loop, not the dependency (M16, D-106).
20. A dependency's restart is its own test case: run the integration suite twice on one stack, or restart the dependency mid-suite. A client pool can keep connections the server closed, and a suite whose only outage test runs last never meets them (M17, D-106).
