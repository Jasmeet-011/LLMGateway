# D-094 M14 integration tests: keys and table reads through `docker compose exec`; Postgres stays unpublished

- **Decision:** Extends D-081 for M14. The `integration` tests still reach the gateway only at `LLMGATEWAY_BASE_URL`, under D-081's guard. They make and revoke keys by running the real CLI in the api container (`docker compose exec -T api python -m llmgateway.keys ...`), and read the table with `psql` in the postgres container (`docker compose exec -T postgres psql ...`), with every value passed as a psql variable (`-v name=value`, quoted by psql as `:'name'`), never written into the SQL text (CLAUDE.md). Postgres's port stays unpublished (D-078). They prove: a valid key gets 200, for a stream too; a missing, malformed, unknown, wrong-secret or revoked key gets the same 401; a key used before it is revoked gets 401 within the cache time plus a margin; `/healthz` needs no key; every column of every row holds no key and no secret, and `key_hash` is the SHA-256 of the created key; and, last in the run, with Postgres stopped an uncached valid key gets 503 `auth_unavailable`, and after Postgres is started again the same key gets 200. The existing D-081 tests use a key made the same way. Unit tests use a fake store; tests that need no database but a real driver (asyncpg against a closed port and against a server that never answers) run in the default suite.
- **Why:** Going through the CLI and the real api tests what an operator does, on the real image. `psql` reads the table as stored, not as the gateway's code reports it. Keeping Postgres unpublished keeps D-078's development password harmless.
- **Alternatives:** Publish Postgres on `127.0.0.1` and connect from pytest (a second path to the database that operators do not use); GitHub `services:` (D-080).
- **Risk:** The tests need the `docker` CLI and the Compose project in the working directory. The outage test stops a service; if its restore fails, later tests in the same run fail, so it runs last and restores in a `finally`.
- **Revisit when:** The stack runs somewhere `docker compose exec` cannot reach.
